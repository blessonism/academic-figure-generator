## 现状速览

**项目定位**：AI 驱动的学术论文配图自动生成 SaaS 平台

**已有能力**：
- 完整的端到端工作流（上传→解析→Prompt→生成）
- 基础按量付费 + 余额系统（CNY）
- Marketplace 内容分享
- BYOK（Bring Your Own Key）支持
- 完整的管理后台与用户管理
- React 19 + FastAPI + Celery + MinIO 的现代化技术栈

**核心缺口**：
- 无订阅制 → 缺乏经常性收入（MRR）
- 无 Landing Page → 无获客入口
- 仅支持 Linux DO Credits → 用户群受限
- 无产品差异化壁垒 → 易被复制

## 一、商业模式升级（最高优先级）

### 1.1 订阅制 + 按量付费混合模型

当前只有按量付费（pay-per-use），**缺乏经常性收入（MRR）**，这是 SaaS 估值的命脉。

| 层级 | 月费 | 包含额度 | 超额单价 | 特权 |
|------|------|---------|---------|------|
| **Free** | ¥0 | 5 张/月（1K） | 不可超额 | 水印、无 BYOK |
| **Pro** | ¥49 | 100 张/月 | ¥1.0/张 | 无水印、BYOK、4K、优先队列 |
| **Team** | ¥199 | 500 张/月 | ¥0.8/张 | 协作空间、API 访问、批量生成 |
| **Enterprise** | 定制 | 不限 | 议价 | 私有部署、SLA、专属支持 |

**设计逻辑**：
- **Free** 是漏斗入口，用水印自然传播
- **Pro** 是主要利润来源（覆盖 80% 个人用户）
- **Team** 切入实验室/课题组场景
- **Enterprise** 切入高校/出版社私有部署

### 1.2 支付渠道多元化

目前仅支持 Linux DO Credits，**严重限制了用户群**。需要接入：
- **支付宝 / 微信支付**（国内主流，覆盖 90% 中国用户）
- **Stripe**（国际用户，支持 USD/EUR）
- **年付折扣**（8 折）刺激长期留存，提升 LTV

### 1.3 关键指标定义

| 指标 | 定义 | 目标值（首年） |
|------|------|---------------|
| MRR | 月度经常性收入 | ¥30,000 |
| ARPU | 每用户平均收入 | ¥35 |
| 付费转化率 | 注册→付费 | 5% |
| 月流失率 | Churn Rate | < 8% |
| LTV/CAC | 用户价值/获客成本 | > 3 |

## 二、增长引擎（获客）

### 2.1 Landing Page + SEO

目前没有公开营销页面，用户无法通过搜索发现产品。需要：
- **独立 Landing Page**：价值主张、Demo 视频、定价表、用户案例、FAQ
- **博客 / 内容营销**：「如何用 AI 生成 CVPR 论文配图」等长尾 SEO 文章
- **公开 Gallery 页面**：Marketplace 的公开只读版本，可被搜索引擎索引，作为流量入口
- **学术外链建设**：在知乎、SemanticScholar、Reddit r/academia 等社区曝光

### 2.2 裂变机制

- **邀请奖励**：邀请人和被邀请人各得 10 张免费额度
- **分享水印**：Free 用户图片带品牌水印 → 自然传播
- **学术社区运营**：知乎 / 小红书 / Twitter / 微信公众号上的学术圈推广
- **导师/课题组推广分成**：为教授提供「课题组专属链接」，注册用户 5% 返佣

### 2.3 Marketplace 作为增长飞轮

当前 Marketplace 已有基础，但需强化：
- **公开浏览**（无需登录）→ 吸引流量
- **「一键复用此风格生成」** → 转化注册
- **创作者分成**（下载收费的 10-30% 归创作者）→ 吸引内容生产者
- **热门排行榜 / 每周精选** → 内容运营钩子

## 三、产品差异化（护城河）— 深度展开

> 这一节是本文档的核心。**护城河 ≠ 功能堆砌**，而是「让用户离不开你」的结构性壁垒。
> 学术配图赛道的竞品（DALL-E、Midjourney、SciDraw、BioRender）各有侧重，我们的差异化必须聚焦在「学术场景的深度专精」而非「通用图像生成的广度」。

### 3.1 学术场景专精：从「能用」到「专用」

#### 3.1.1 会议 / 期刊风格模板库

**问题**：通用 AI 生成的图片往往不符合学术期刊的视觉规范，研究者还要二次调整。

**解决方案**：建立「会议级风格模板库」，覆盖主流学术发表场景。

| 类别 | 示例模板 | 特征 |
|------|---------|------|
| **CV 顶会** | CVPR / ICCV / ECCV | 紧凑布局、深色架构图、强调对比 |
| **NLP 顶会** | ACL / EMNLP / NAACL | 流程图为主、注重数据流动 |
| **ML 顶会** | NeurIPS / ICML / ICLR | 数学公式融合、多子图对比 |
| **Nature 系列** | Nature / Science / Cell | 精美排版、矢量优先、配色克制 |
| **IEEE 期刊** | TPAMI / TIP / TNNLS | 黑白友好、双栏适配 |
| **ACM 期刊** | SIGGRAPH / CHI / TOG | 创意性强、视觉表达丰富 |

**技术实现**：
```python
# backend/app/core/prompts/style_templates.py
STYLE_TEMPLATES = {
    "cvpr_style": {
        "name": "CVPR/ICCV 顶会风格",
        "system_prompt_addon": "Use compact 2-column layout, dark backgrounds for architecture diagrams...",
        "color_palette": "okabe_ito",
        "aspect_ratio_default": "16:9",
        "typography": "Helvetica, sans-serif",
        "preview_image": "templates/cvpr_preview.png",
    },
    # ...
}
```

**变现钩子**：
- Free 用户仅能使用 3 个基础模板
- Pro 用户解锁全部 50+ 模板
- Team 用户可定制专属模板（实验室品牌色、Logo）

#### 3.1.2 图表类型深度优化

学术图表不是「画一张图」那么简单，每种图都有自己的语言：

| 图表类型 | 学术规范 | 当前 AI 痛点 |
|---------|---------|-------------|
| **架构图** | 模块清晰、数据流明确、维度标注 | AI 容易画成抽象艺术 |
| **流程图** | 节点形状有语义（菱形=判断，矩形=过程） | AI 不理解图形语义 |
| **消融实验表** | 表格 + 颜色编码、显著性标注 | AI 几乎不会做表格 |
| **实验对比图** | 多子图对齐、统一坐标轴 | AI 无法保证对齐 |
| **注意力可视化** | 热力图叠加、保留原图细节 | AI 容易破坏原图 |
| **训练曲线** | 多曲线对比、置信区间 | AI 数据不真实 |
| **数据集示例图** | 网格布局、统一比例 | AI 比例混乱 |

**解决方案**：每种图表类型专门做 Prompt 工程 + 后处理管线：
- 架构图 → 接入 Mermaid / Graphviz 作为预渲染层，AI 只负责美化
- 表格 → 接入 LaTeX 表格生成器，输出标准 `tabular` 代码
- 训练曲线 → 接入 Matplotlib 模板，用户传数据，AI 选风格

**护城河价值**：通用 AI 工具无法做到这种深度，需要垂直领域知识。

#### 3.1.3 矢量格式输出（学术期刊刚需）

**痛点**：几乎所有 SCI 期刊要求矢量图（PDF/EPS/SVG），但当前所有 AI 生图工具都只能输出位图。

**解决方案**：
- **方案 A**：生成 SVG 优先的图（用 SVG 生成模型 / Mermaid / D3 模板）
- **方案 B**：位图 → 自动矢量化（Vectorizer.AI 同类技术）
- **方案 C**：生成时直接产出可编辑的 LaTeX TikZ 代码

```python
# backend/app/services/vector_service.py
class VectorExportService:
    async def export_as_svg(self, image_id: str) -> bytes: ...
    async def export_as_pdf(self, image_id: str) -> bytes: ...
    async def export_as_eps(self, image_id: str) -> bytes: ...
    async def export_as_tikz(self, image_id: str) -> str: ...
```

**变现钩子**：矢量导出仅 Pro 及以上用户可用，是 Free→Pro 的核心转化点。

### 3.2 论文级工作流：从「单图」到「全篇」

#### 3.2.1 论文智能解析 → 自动配图建议

**当前流程**：用户上传论文 → 人工选段落 → 生成图片

**升级流程**：用户上传论文 → AI 自动识别需要配图的位置 → 一键批量生成

**实现要点**：
1. **段落分类器**：用 LLM 判断每个段落是否需要配图（模型介绍、实验结果、案例分析）
2. **图表类型推荐**：根据段落内容推荐合适的图表类型（架构图/流程图/数据图）
3. **批量生成 UI**：列表展示所有建议，用户勾选 → 后台 Celery 批量执行
4. **进度可视化**：SSE 实时推送每张图的状态

```python
# backend/app/services/paper_analysis_service.py
class PaperAnalysisService:
    async def suggest_figures(self, document_id: str) -> List[FigureSuggestion]:
        """
        返回结构：
        [
            {
                "section": "3.2 Model Architecture",
                "figure_type": "architecture",
                "confidence": 0.92,
                "suggested_prompt": "...",
                "rationale": "Section describes a 3-layer encoder-decoder..."
            },
            ...
        ]
        """
```

#### 3.2.2 论文插图包导出

生成完所有图后，**一键打包** 为论文插图包：

```
my_paper_figures.zip
├── figures/
│   ├── fig1_architecture.pdf  (矢量)
│   ├── fig1_architecture.png  (位图备用)
│   ├── fig2_flowchart.pdf
│   └── ...
├── latex_snippets.tex  (现成的 \includegraphics 代码)
├── captions.md  (AI 生成的图注建议)
└── README.txt  (使用说明)
```

**LaTeX 代码示例**（自动生成）：
```latex
\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{figures/fig1_architecture.pdf}
\caption{Overall architecture of our proposed model. The encoder...}
\label{fig:architecture}
\end{figure}
```

**护城河价值**：这是从「图片工具」升级为「论文写作助手」的关键一步，**绑定了用户的整个写作流程**。

#### 3.2.3 与论文写作工具集成

- **Overleaf 插件**：直接在 Overleaf 中调用我们的 API 生成图片
- **VS Code 插件**：写 LaTeX 时一键生成配图
- **Notion / Obsidian 插件**：研究笔记中插入 AI 配图
- **Zotero 集成**：从文献库中选论文 → 直接生成对比图

**战略意义**：通过插件矩阵深入用户的真实工作流，**离开我们的成本变高**。

### 3.3 协作功能：从「个人工具」到「实验室基础设施」

#### 3.3.1 团队空间（Team 层级核心功能）

**场景**：导师 + 5 个研究生组成课题组，共享一个配图素材库。

**功能设计**：
- **共享项目**：课题组所有成员可访问、编辑同一个项目
- **角色权限**：Owner（导师）/ Editor（研究生）/ Viewer（合作者）
- **共享额度池**：团队购买 500 张/月，所有成员共用
- **审计日志**：谁在什么时候生成了什么图，便于学术诚信追溯

```python
# backend/app/models/team.py
class Team(Base):
    id: int
    name: str
    owner_id: int
    plan: str  # team / enterprise
    monthly_quota: int
    quota_used: int

class TeamMember(Base):
    team_id: int
    user_id: int
    role: str  # owner / editor / viewer
    joined_at: datetime
```

#### 3.3.2 评论 / 标注 / 修改建议

**场景**：导师审阅学生生成的图，提出修改意见。

**功能**：
- 在图片上添加标注（"这里颜色太亮"、"模块顺序应该反过来"）
- 修改建议直接转化为新一轮 Prompt 编辑
- 版本对比（A vs B 并排展示）

#### 3.3.3 版本历史与回溯

每张图保留完整的生成历史：
- v1: 初始生成
- v2: 修改了配色
- v3: 调整了布局
- ...

支持任意版本回溯、Diff 对比、Fork 分支（基于 v2 派生新版本）。

**护城河价值**：协作和版本管理一旦被实验室采用，**迁移成本极高**，类似 GitHub 之于代码。

### 3.4 数据资产化：让用户的数据为自己服务

#### 3.4.1 个人风格学习

**场景**：用户生成了 50 张图后，AI 应该学会他的偏好（喜欢冷色调、紧凑布局）。

**实现**：
- 记录用户的修改偏好（哪些图被采纳、哪些被重新生成）
- 训练个性化 Prompt 增强器（轻量级 RLHF）
- 「我的风格」按钮：一键应用个人风格

#### 3.4.2 实验室视觉系统（VI System）

**场景**：MIT CSAIL 实验室希望所有论文配图都符合实验室视觉规范。

**功能**：
- 上传实验室 Logo、标准色卡、字体
- 所有生成的图自动应用 VI 规范
- 输出物带 "Generated by MIT CSAIL Lab" 水印（Pro+ 可关闭）

**变现**：实验室 VI 系统是 Enterprise 层级的核心卖点。

#### 3.4.3 引用网络可视化

**场景**：Survey 论文需要展示引文之间的关系网络。

**功能**：
- 上传 BibTeX 文件 / DOI 列表
- 自动从 SemanticScholar / OpenAlex 拉取引用关系
- 生成漂亮的引文网络图（节点=论文，边=引用）

**差异化**：竞品都没有这种数据驱动的图表生成能力。

### 3.5 模型层差异化：多模型路由

不要绑死在单一图像生成模型上。建立**模型路由层**：

| 模型 | 适用场景 | 成本 |
|------|---------|------|
| **NanoBanana (Gemini 3 Pro)** | 当前默认，平衡型 | 中 |
| **Flux Pro** | 写实风格、高质量 | 高 |
| **DALL-E 3** | 创意性强、概念图 | 高 |
| **SDXL + 学术 LoRA** | 私有部署、低成本 | 极低 |
| **Mermaid / Graphviz** | 精确架构图、可编辑 | 几乎为零 |
| **Matplotlib / Plotly** | 数据可视化、训练曲线 | 几乎为零 |

**智能路由策略**：
- 用户选「架构图」→ 优先 Mermaid 预渲染 + AI 美化
- 用户选「实验数据图」→ 优先 Matplotlib 模板
- 用户选「概念示意图」→ 优先 Flux Pro
- 用户选「快速预览」→ 用 SDXL 本地推理（成本极低）

**护城河价值**：竞品换模型很容易，但「为不同学术场景选对模型」需要大量经验积累。

| Overleaf 插件 | 中 | ⭐⭐⭐⭐ | 中 | **P1** |
| 团队协作 | 高 | ⭐⭐⭐⭐ | 中 | **P1** |
| 多模型路由 | 中 | ⭐⭐⭐ | 中 | **P1** |
| 个人风格学习 | 高 | ⭐⭐⭐ | 高 | **P2** |

## 四、技术优化（转化率 & 留存）

### 4.1 首次体验优化

- **无需注册即可试用**：上传论文 → 生成 1 张预览图（带水印）→ 注册解锁
- **引导式 Onboarding**：3 步引导（上传→选风格→生成）
- **预置示例项目**：新用户自动创建一个带范例的 Demo 项目
- **空状态优化**：每个空页面都有清晰的 CTA 引导

### 4.2 生成质量 & 速度

- 接入更多图像模型（Flux、DALL-E 3、Midjourney API）作为可选后端
- 实现「快速预览」（低分辨率秒出）+ 「高清渲染」（付费高分辨率）
- 生成失败自动切换备用模型
- 排队优化：付费用户优先队列，明确告知预计等待时间

### 4.3 数据驱动运营

当前缺乏业务分析能力，需要：
- **用户行为追踪**（注册→首次生成→付费 转化漏斗）
- **留存分析**（日活/周活/月活、流失预警）
- **A/B 测试框架**（定价、UI、引导流程）
- **NPS 调研**：定期收集用户满意度
- **取消订阅原因调研**：流失用户的反馈是金矿

**技术选型建议**：
- 行为追踪：PostHog（开源 + 自托管）/ Mixpanel
- 错误监控：Sentry
- A/B 测试：GrowthBook（开源）

## 六、核心判断与决策框架

### 6.1 核心判断

你的产品已经有了**完整的技术底座**（认证、支付、存储、异步任务、Marketplace），但目前更像是一个「技术项目」而非「商业产品」。

**最关键的三件事**：
1. **订阅制**：从按量付费转向 MRR，这是 SaaS 估值的基础
2. **免费试用 → 付费转化漏斗**：让用户零门槛体验到价值
3. **支付渠道**：脱离 Linux DO 生态，面向更广泛的学术用户群

### 6.2 护城河的本质

**功能可以被抄，但以下三件事很难被抄**：
1. **学术领域的深度知识沉淀**（哪种期刊偏好什么样的图）
2. **用户工作流的深度绑定**（论文写作工具集成、团队协作）
3. **数据资产的复利效应**（用户越多、模板越好、风格越准）

### 6.3 资源分配建议

如果只能投入 1 个人 / 月，按以下顺序：
1. 订阅制 + 支付宝接入（变现）
2. 矢量导出（差异化 + 转化）
3. 会议风格模板库（差异化）
4. 论文智能解析 + 批量生成（核心护城河）

如果有 2-3 人的团队：
- 1 人负责商业化（订阅、支付、Landing Page）
- 1 人负责差异化功能（模板、矢量、批量）
- 1 人负责增长（SEO、Marketplace、社区）

### 6.4 风险与对冲

| 风险 | 影响 | 对冲策略 |
|------|------|---------|
| OpenAI/Google 推出竞品 | 高 | 深耕学术垂直，建立用户工作流绑定 |
| 学术圈付费意愿低 | 中 | Team/Enterprise 切入实验室，由 PI 付费 |
| 模型 API 涨价 | 中 | 多模型路由 + 自部署 SDXL 兜底 |
| 内容版权争议 | 中 | 明确生成内容归属 + 学术诚信声明 |
