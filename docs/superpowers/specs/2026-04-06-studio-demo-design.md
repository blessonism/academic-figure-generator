# Studio 重设计 Demo 设计文档

**日期：** 2026-04-06

## 目标

为新版 Studio 先交付一个独立的半交互 Demo 页面，不接入真实接口，只验证以下内容：

- 混合型工作流是否比现有 Studio 更清晰
- 阶段导航、主工作区、上下文抽屉、底部动作条是否形成更好的任务流
- 新视觉语言是否适合本项目后续正式重构

本次 Demo 不替换现有 `/projects/:id` 页面，避免影响正式流程。

## 设计原则

### 1. 默认像向导，深入时像工作台

- 页面默认只强调当前阶段的主任务
- 相关上下文按需展开，而不是长期并列堆叠
- 允许在阶段间跳转，但会保留明确的阶段状态提示

### 2. 主任务永远居中

Studio 页面拆成五个区域：

1. 顶部项目头部
2. 阶段导航
3. 当前阶段主工作区
4. 可折叠上下文面板
5. 底部动作条

其中主工作区是唯一持续高优先级区域，其他区域都是辅助层。

### 3. 状态反馈统一收口

- 轻量状态：按钮文案、标签、局部提示
- 中等级状态：阶段摘要、内联提示卡
- 高优先级状态：底部浮动动作条
- 完成反馈：阶段完成卡片

## Demo 范围

本次 Demo 只覆盖三个最能体现新交互节奏的阶段：

- Scope：确认范围
- Prompt：筛选草案
- Render：提交出图

不实现真实上传、解析、生成和下载行为，只使用 mock 数据模拟：

- 已解析章节
- Prompt 草案列表
- 出图资产与预算信息

## 页面结构

### 顶部项目头部

负责承载：

- 项目名与状态
- 当前模式说明（Studio Demo）
- 关键快捷动作：打开上下文、重置 Demo、查看当前阶段提示

### 阶段导航

采用“可展开阶段条”而不是传统 tabs：

- 当前阶段显示完整标题、描述和状态
- 非当前阶段收缩为紧凑按钮
- 被阻塞阶段显示原因，但 Demo 中允许跳转预览

视觉上参考 `/Users/suki/code/component/src/components/ui/expandable-tabs.tsx` 的展开感，但采用本项目原生样式体系实现。

### 主工作区

每个阶段都遵循统一结构：

- 阶段标签
- 标题与当前目标
- 主交互模块
- 下一步提示

### 上下文面板

右侧面板默认可切换显示/隐藏，负责承载：

- 当前阶段摘要
- 输入来源
- 风险与注意项
- 推荐下一步

它替代现有 Studio 中常驻的健康检查与检查器双侧信息。

### 底部动作条

当出现待保存、待确认、待执行动作时显示浮动条：

- Scope 阶段：确认范围
- Prompt 阶段：保存草案决策
- Render 阶段：提交生成任务

体验上参考 `/Users/suki/code/component/src/components/ui/unsaved-changes.tsx`，但只保留适合本项目的状态。

### 阶段完成卡

在用户完成某阶段关键动作后显示完成卡：

- Scope：范围已确认
- Prompt：草案已选定
- Render：生成任务已提交

体验上参考 `/Users/suki/code/component/src/components/ui/order-confirmation-card.tsx` 的“完成反馈”结构，但内容改成项目流程导向。

## 视觉方向

采用“学术创作工作台”气质：

- 明亮底色 + 柔和中性色分层
- 局部使用青蓝与琥珀作为工作流强调色
- 卡片使用较大圆角、轻阴影和明确留白
- 不堆玻璃态，不追求炫技动画，只在关键区域做轻量过渡

可借鉴 `/Users/suki/code/component` 中组件的节奏感和层次感，但应保持本项目语义化和可维护性。

## 非目标

以下内容不在本次 Demo 范围内：

- 所有阶段的完整业务逻辑
- 最终视觉定稿
